# 用户授权与密码重置权限修复

校园统一登录的真实接入按用户本轮指示暂缓。本次直接基于 `dev@33ef8c4` 修复本地账号管理，不依赖 PR #40，也不启用校园认证或操作业务数据库。

## 已复现的问题

- 重置密码接口在目标用户没有默认组织时跳过权限校验，学生、支部审核员和学院管理员都能收到该账号的新密码。
- 创建用户只检查默认组织，未检查每条角色授权的组织，学院管理员能给新账号授予其他学院的角色。
- 多身份账号默认组织在本学院时，学院管理员可以修改或重置带有校级角色、其他学院授权的账号。
- 角色列表、组织编号、启用状态缺少服务端完整校验；例如字符串 `false` 会被当成启用。
- 用户更新直接把请求体写入审计，忽略的 `password`、`api_key` 字段也会被保存。

用随机隔离 PostgreSQL schema 和虚构用户复现了前四个越权请求，修复前测试均失败；没有探测或修改真实账号。

## 修复后的行为

全局用户管理员继续按现有权限管理账号。学院管理员必须同时具备目标默认组织和全部角色授权组织的管理权限，不能管理校级授权账号。未挂组织账号仅全局用户管理员可操作。学生本人仍可改基础资料，不能更改自身授权或启用状态。

创建和更新共用服务端授权校验：至少一条有效角色，组织存在且启用、范围可管理、无重复授权，编号和开关类型正确。所有校验先于资料修改、账号插入和旧授权删除。合法的本学院创建、资料维护及重置密码流程保留。

用户更新审计只记录已知字段名，不保存请求字段值；新建与重置密码响应带 `Cache-Control: no-store, private`。本次不改写历史审计记录，也不声称清理了历史记录中可能已经存在的内容。

## 验证

独立 PostgreSQL：新增 20 个回归，覆盖跨学院创建、无组织账号及校级多角色账号重置、授权替换、非法角色/重复授权、字符串开关、审计保密，以及合法学院管理和自助资料维护。

本分支完整后端 812 项、桌面 7 项，共 **819 passed / 0 skipped**。前端无代码变更。现有 Starlette TestClient/httpx 弃用提示不影响结果。

本修复是独立的用户管理修复，不等于已完成真实学校服务、目标服务器、所有真实材料或另一台干净机器的验收。旧 Windows 候选包未包含此修复，整合新候选包时需重新构建并检查其源码提交标识。
