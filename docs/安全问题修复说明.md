# 截图问题逐项处理

本轮以 `dev@be79bd4` 为基础，整合 PR #22、#23 的已有修复并补齐剩余项目。修复分支为 `fix/security-hardening`，只有合并并升级运行版本后才会对部署生效。

1. **大模型请求脱敏**：沿用 dev 已有的统一请求边界脱敏，回归覆盖姓名、学号、手机号、身份证、模板和嵌套变量，且不修改原文。
2. **SQL 中的管理员密码哈希**：公开备份改为不可登录的恢复标记，首次启动生成新密码并撤销旧令牌。检测到已有管理员仍使用历史公开的那一个哈希时也会轮换；其他自定义密码不变，停用账户不自动启用。Git 历史中的旧内容仍存在，不改写仓库历史。
3. **演示账号提示默认开启**：后端缺省关闭，只有明确启用演示模式才返回提示。
4. **更换模型地址沿用密钥**：临时测试地址和已保存地址两条路径都校验。更改已保存地址须重新提供密钥；密钥绑定完整接口地址。请求在同一配置快照中取地址和密文，防止并发修改导致密钥串发。
5. **无条件信任 X-Forwarded-For**：统一解析客户端 IP，默认忽略转发头；仅显式配置的可信直连代理可提供转发链。两个自带 Uvicorn 入口关闭自动代理头处理，避免应用校验前改写来源。
6. **登录错误信息可识别账号存在性**：未知、错密、停用、锁定全部返回相同 401 正文；未知账号也执行一次 bcrypt。内部失败计数、锁定和审计仍保留，正确密码不能绕过锁定。
7. **上传先整份读入内存**：材料初传和补交有界读取；ZIP 分块写入随机临时文件，按实际字节检查限额。超限、取消、读写错误、入队失败均清理本轮文件。请求接收阶段另设实际字节总上限，不依赖 Content-Length。
8. **ZIP 同名覆盖与实际解压计数**：沿用 dev 的随机文件名、独占创建、逐块实际计数及失败清理，通过回归验证。
9. **存储路径 startswith 判断**：沿用 dev 的 `is_relative_to` 校验，拒绝同名前缀的兄弟目录。
10. **无 dist 时暴露前端源码**：只挂载存在 `dist/index.html` 的构建目录。未构建和构建不完整时仅提供 API，源码、package.json 不再作为静态文件提供。
11. **异常诊断、版本化迁移、CI**：HTTP 响应附诊断编号，后台任务和审核/解析记录异常类型及调用位置，不记录正文、密钥、异常原始值；不可预期的任务/报告错误也不将原始异常展示给用户。迁移使用冻结 SQL、checksum 账本、事务和并发锁，支持空库及完整旧库接管。新增 GitHub Actions，分别执行 PostgreSQL 后端回归、前端单元/交互/构建、Windows 桌面回归；数据库用例被跳过时 CI 失败。

部署参数、日志位置和代理配置见 [RUN.md](RUN.md)，迁移机制及旧库接管见 [数据库迁移说明](数据库迁移说明.md)。本轮数据库验证使用新建的本机临时实例，没有修改现有业务数据库，也没有发布新的 EXE。
