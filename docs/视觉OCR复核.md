# 视觉 OCR 复核

## 使用方式

1. 系统管理员进入“系统配置 → 视觉 OCR 复核”，填写支持图片输入的模型接口地址、模型名称和独立 API 密钥。地址为兼容 Chat Completions 的根地址，通常以 `/v1` 结尾，不包含 `/chat/completions`。
2. 保存后点击“测试视觉 OCR 复核”。测试向已保存的接口发送内置虚构中文图片，验证图片输入和结构化转录结果；不会发送真实档案。
3. 按材料使用要求，打开“启用视觉 OCR 复核”和“允许将材料原图区域发送至所配置的模型服务”。默认均关闭。图片不经过文字脱敏；可配置本地部署的视觉模型服务。
4. 新上传或重新解析扫描 PDF、PNG/JPG 材料后，在材料详情的“解析文本”查看建议。默认只复核本地 OCR 置信度低于 0.9 的文字块；没有识别文字时复核整页。对于手写、疑似漏字或本地 OCR 高置信度误识别，可开启“复核所有扫描页”。有正常文本层的 PDF 和 DOCX 不发送。
5. 点击“查看原图区域”可查看对应版本、页码和高亮区域，再选择“核对后填入校正文本”。填入仅修改当前草稿，仍需“保存校正”或“保存并重新校验”。有重复原文或已经人工修改的位置不会被自动替换，可手动编辑。姓名、日期等均需人工核实。

## 结果与回退

- 本地 `full_text`、页面文字、文字块坐标和置信度不被模型覆盖；候选文字存放于 `pages[].vision_reviews`，包含原文、建议、模型、区域位置、自报置信度、不确定标记和复核状态。无需数据库结构迁移。
- 候选建议不直接参与分类、日期抽取或审核。人工保存后沿用现有 `corrected_text` 校正与审计流程；结构化时间节点仍须在原有“时间节点抽取”区域单独核对、校正，修改文字不会静默更改已锁定节点。
- 建议记录用于追溯，不会随人工保存改成“模型已通过”；已采纳内容以保存的校正文本为准。重新解析会刷新自动识别和候选建议，已有人工校正字段继续保留。
- 网络失败、超时、无效响应等保留本地结果并提示，不使整份材料解析失败。同一份材料遇到接口失败后不再逐块重试。
- 默认每份材料最多复核 6 个区域，可设为 1–20；单次请求超时默认 45 秒，可设为 1–120 秒；进程内最多 2 个并发请求，等待并发槽也有超时。达到区域上限会提示其余部分仍为本地结果。
- 视觉密钥独立加密保存、不回显，并绑定接口地址。更换地址须重新填写密钥或显式清空。普通文字审核模型的密钥不用于图片请求。测试只使用已保存配置。

## 验证与边界

2026-10-25：独立 PostgreSQL 数据库下后端与桌面回归 519 项通过，包含候选建议持久化、人工校正 API 和禁止覆盖原文；前端逻辑 64 项通过，界面场景 73 项通过，生产构建通过。

HTTP 边界测试检查了真实图片编码、局部裁剪、模型请求格式、输出校验、超时及错误回退、发送开关、区域上限和密钥隔离。外部服务使用可控测试响应，未配置或调用付费外部模型，尚未测得真实手写或打印体准确率提升。启用前应使用允许发送的脱敏样本验收所选模型。

本次为源码功能交付，现有旧版桌面 EXE 不会自动更新；部署需使用更新后的源码，或重新构建桌面程序。

接口格式依据：[图像输入官方文档](https://developers.openai.com/api/docs/guides/images-vision)。兼容服务需支持 `messages[].content` 中的 `text` 和 `image_url`（PNG data URL），并返回 `choices[0].message.content` 内的 JSON 转录结果。
