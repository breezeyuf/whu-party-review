# OCR 部署与验收（RapidOCR）

2026-10-26 根据 PR #30/#31 复审及用户选型，统一使用 `rapidocr==3.10.0`、`onnxruntime==1.31.0`。PaddleOCR 运行分支已移除，旧配置名称仅用于升级映射，不会导入旧引擎。唯一解析重试路由保留在整合分支，不合入另一份 PaddleOCR 实现。

## 安装与自检

安装基础依赖后，按 [RUN.md](RUN.md) 使用官方 PyPI 源安装 `backend/requirements-ocr.txt`。不需要卸载 `opencv-python-headless`。Windows 桌面锁定文件包含已实测的 OCR 依赖；打包环境须先安装并自检。

在仓库根目录运行 `python backend/ocr_check.py --engine rapidocr --dpi 200`，或在系统设置中保存 OCR 配置后测试。两者使用同一个 `ai.ocr.probe`。测试加载实际模型、识别内置虚构中文图片，并校验 2026-09-15 能被日期解析器找到；失败时返回 `ok=false`、命令退出码非零。依赖可发现不代表模型运行成功。

`auto` 未安装依赖时回退为预览及人工核对；`rapidocr` 显式启用时故障标记 FAILED；`none` 立即关闭识别。超时或进程崩溃会回收子进程，后续可重建并重试。重新解析保留人工文本、字段、节点修正和删除决定；失败时保留此前可用解析。

## 日期与原文定位

RapidOCR 可能返回 `２ 0 ２ ６ 年9 月15 日` 或 `2 0 2 6 - 0 9 - 1 5`。OCR 边界先执行 NFKC，去除同行数字间空白及日期内部排版空白，再把相同规范化文本写入页面块和全文。日期匹配偏移仍对应其输入文本，不改变 `find_dates` 的原文偏移规则。

每个 OCR 文本块另存 `raw_text` 保留引擎原始输出，原件不修改，框坐标继续对应预览页面。规范化不会把两行末首的数字拼起来，也不补造日期或修正非法日期。

回归覆盖模拟的全角/空格输出，以及实际生成的图片型 PDF 和 PNG，经真实 RapidOCR 推理后抽出日期节点并定位原图。数据库回归还验证 T02 节点实际保存为 2026-09-15；缺少可选依赖的 CI 中，真实推理用例明确跳过，不能计为通过。

## 离线部署与验收边界

当前默认 ONNX 模型来自所安装 RapidOCR 包内模型目录；桌面构建收集这些数据及 ONNX Runtime。正式离线分发前，在干净环境运行同一自检并确认三个模型与所需运行库齐全；不提交模型文件或用户材料到 Git。

自检与合成扫描件证明打印中文、日期、解析路径和定位可运行，不能替代真实拍照、倾斜模糊、多栏、手写、签名或印章准确率验收。视觉 LLM 复核仍为独立、默认关闭的可选能力，需人工确认候选文字，不自动覆盖材料证据。
