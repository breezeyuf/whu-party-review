# 模型输出校验与报告降级

本项基于 PR #8 的脱敏提交 `25c5d1aa6583f9319e1d3186abebae53a26e2427`，修复模型坏输出被当成有效审核结果、置信度 0 被默认成 0.6，以及模型失败后报告仍显示规则加模型的问题。

## 输出接收规则

统一模型入口校验 Chat Completions 的响应结构，要求至少一个 choice 且 message.content 为非空字符串。模型正文必须是 JSON 对象；兼容完整的 JSON Markdown 代码块，不从数组、说明文字或其他错误结构中截取子对象冒充结果。

当前实际内容审核任务 `CONTENT_CHECK` 使用 Pydantic 模型校验：

```json
{
  "issues": [
    {
      "rule_code": "R-C02",
      "snippet": "原文片段",
      "reason": "疑似需要人工核对的原因",
      "confidence": 0.8
    }
  ]
}
```

`issues` 必须是列表，可以为空；每条问题的原文片段和原因必须是非空字符串，confidence 必须是 0 至 1 的有限数值。缺字段、数字字符串、布尔值、负数、越界或非有限置信度均视为无效。rule_code 可省略；提供时必须与当前检查的规则匹配。模型提供的其他字段不会覆盖本地规则级别或人工研判标志。

JSON 或结构校验失败会重试一次；仍失败则明确返回错误，不能当成“未发现问题”。网络重试沿用配置；内容检查沿用现有单次网络尝试上限，另允许一次坏输出重试，避免批量审核长时间等待。HTTP 4xx 不重试，连接失败、超时和 5xx 按网络预算处理。错误信息不回显供应商响应正文或模型原始输出。

连接测试等现有非内容审核调用继续接收 JSON 对象；尚未接入的分类、抽取、建议任务，本次没有新增其业务逻辑或任务专用结构。

## 置信度与报告行为

- 置信度低于 0.5 的问题不写入报告，0 保持为 0；恰好 0.5 可以保留。
- 每次调用最多保留 10 条达到阈值的问题，低置信度条目不占用这 10 个位置。
- 所有接收的语义问题继续标为 `AI_LLM` 且需要人工研判。
- 任一语义检查最终失败时，整份报告撤下本轮模型问题，保留完整性、时间、形式及本地内容规则结果。语义规则统一标记 `SKIPPED`，带有机器可读的 `error` 和展示原因。
- 报告仍可完成，`status=DONE`、`mode=RULE_ONLY`、`degrade_reason` 说明失败原因，保留尝试使用的模型名供追溯。仅规则模式继续进入现有人工接管判断。
- 主动关闭模型时显示“本次未启用大模型”；模型未配置时显示“未配置大模型”。没有适用语义规则或可检查文本时也不宣称执行过模型。
- 复核降级时，待处理的旧语义问题不会因本次未检查而自动标为已解决；其状态保持 OPEN，计入 unresolved，并在 recheck_summary 增加可选计数 not_rechecked。已经人工驳回的误报不重新列为待核对问题。完成语义复核且确认问题未再出现时，才按原流程标为已解决。

本次延续脱敏实现，不改数据库结构、接口地址或现有提交/审核权限。

