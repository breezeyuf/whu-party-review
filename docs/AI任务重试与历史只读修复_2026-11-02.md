# AI 任务重试与历史报告只读修复

基于 PR #45 的整合分支 integration/pr40-pr44，起点 7f558217b25e5a269f3faaf2c326b747d7d63d81。本修复 PR 的目标是该整合分支，不直接合并 main/dev。

## 问题及行为

旧任务重试此前只验证创建人或管理员及任务失败状态，不能替代当前提交包的 AI 检查权限；后台执行也没有重新核验。现在正常发起、重试、执行共用 services/ai_job_policy.py：

- 锁定提交包后核验当前账号、启用组织、实际角色授权、可见范围和既有 can_actions 的 ai_check 判定。普通发起在获得锁后再次检查，避免排队前的状态竞争。
- 新任务保存发起时的角色和组织；执行时使用当前授权核验该身份。已停用、角色撤销、分配变化或材料已进入无权检查的阶段时停止执行。
- 老任务兼容：SELF_CHECK 按学生身份核验；缺少身份记录的审核任务只接受唯一且当前有效的审核身份，不能确定时要求从当前办理页重新发起。
- 重试人和原发起人都需要符合当前权限；系统管理员没有材料审核权限，不能以管理身份绕过 AI 检查条件。其他任务类型保留原重试规则。
- 提交包行锁和排队/运行任务检查共同防止重复检查，包括尚未拆分的批量任务预约。批量失败子任务全部验证通过才重新排队。
- 后台真正执行、批量拆分前再次检查；业务条件不再满足时记录终止原因，不自动反复重排，也不创建报告、替换有效问题或更新最新报告指向。已开始执行的检查沿用原 worker 执行代次保护。

## 历史报告界面

审核工作区任务组件支持只读模式。历史快照或当前角色无检查权限时，可查看状态，不能显示或触发重试；学生历史自查不显示当前任务操作。当前且有权限的报告保留合法失败重试。前端限制不代替服务端校验。

## 网页验收建议

使用专用测试档案：草稿失败任务允许重试；提交后/备案后旧自查重试应拒绝。任务排队后撤销发起人授权或更改到不可审核阶段，后台应停止并保留既有报告。打开历史报告应只有状态展示，没有重试；返回当前有权限报告才可操作。批量部分失败应校验每个失败提交包，不能部分越权排队。

本地已完成数据库/API与模拟界面验证；上述跨角色真实浏览器流程可在整合环境使用专用测试档案进一步验收，不应对真实备案档案试做。
