# PostgreSQL 版本化迁移

应用启动时，`database.init_db()` 调用 `migrations.apply_migrations(engine)`。启动不再重放可变的 `schema.sql` 和 `_HANDOVER_PATCH`。迁移只使用传入引擎当前 `search_path` 的第一个有效 schema；事务内固定到该 schema，避免误用后续 schema 中的同名表。

## 版本记录与执行保证

`schema_migrations` 保存 `version`、SQL 文件名 `name`、SHA-256 `checksum`、是否接管旧基线 `adopted`、应用时间 `applied_at`。SQL 的 CRLF 统一为 LF 后计算 checksum，因此正常的 Windows/Unix 换行转换不会导致漂移。

启动先取得按数据库名和 schema 名计算的 PostgreSQL 事务级 advisory lock，再检查记录和执行迁移。并发启动会排队，后取得锁的进程读取前一个进程已经提交的版本。本次所有待执行 SQL、旧库接管记录、版本记录在同一事务中提交；任意一步失败，整批回滚，不保留半张表或错误的成功版本。前次已成功提交的版本不受影响。

已有记录必须是本程序迁移序列的连续前缀。checksum 或文件名变化、记录断档、数据库版本高于当前程序都会拒绝启动。恢复原来的迁移文件或使用匹配版本的程序后再启动，不通过修改 checksum 记录绕过检查。

当前迁移为：

- `0001_initial_schema.sql`：冻结的初始核心结构、默认字典和默认配置，仅对空 schema 执行；循环外键检查限定到目标表。
- `0002_handover.sql`：增加人工接管字段、接管记录表和索引，兼容已有同名结构。
- `0003_import_password_files.sql`：增加一次性导入密码文件表和过期索引。
- `0004_schema_scoped_foreign_keys.sql`：为旧脚本曾因其他 schema 存在同名约束而遗漏的三条循环外键补齐约束。保留现有行；存在违反外键的数据时迁移失败并整体回滚，交由维护者核对数据。

## 空库与现有数据库

空 schema 自动执行全部迁移；默认规则、管理员初始化仍由原应用流程负责，迁移不包含用户密码或演示账号。

未有版本记录的旧库，仅在 `schema_meta` 的 `schema_version` 为 `1`，且 35 张核心表及冻结字段清单完整时自动接管。接管将 0001 记录为 `adopted=true`，跳过整个基线 SQL，然后执行缺少的增量。接管不会重建既有表、重置系统设置、更新账号密码、重写业务行或替换既有触发器。额外的业务字段和自定义表会保留。陌生的非空库、残缺结构或未知旧版本拒绝自动接管，不猜测其结构。

仓库中 `database/party_review_20261017.sql` 恢复的完整 public 数据库和旧启动机制初始化的当前结构都属于支持的接管对象。公开 dump 自身包含清理、建表和数据恢复语句；这些语句只用于人工恢复，应用迁移器不会执行 dump。迁移测试把该真实 dump 的 SQL 对象名改写到随机测试 schema，COPY 数据原样传入，并逐表验证接管前后数据相同。

`schema_meta.schema_version=1` 保留为历史结构标记。新版本以 `schema_migrations` 为准，不在每次启动时更新历史标记的时间。`schema.sql` 保留供结构参考和旧测试使用；兼容常量 `_HANDOVER_PATCH` 也保留，但应用启动不再执行它。

部署前按现有运维流程备份数据库。升级后可以只读查询实际状态：

```sql
SELECT version, name, checksum, adopted, applied_at
FROM schema_migrations
ORDER BY version;
```

## 添加下一版

在 `backend/migrations/sql/` 新增连续编号的文件，例如 `0005_add_example.sql`。文件名只含四位版本号、下划线、小写字母或数字。已经发布的文件和旧库字段清单保持不变，修复通过新增版本表达。

迁移文件必须能在 PostgreSQL 事务中执行，不写 `BEGIN`、`COMMIT`、`ROLLBACK`，也不使用 `CREATE INDEX CONCURRENTLY`、`VACUUM` 等事务外命令。文件是随程序发布的受信源代码，不接受用户上传 SQL。涉及既有数据的增量应明确处理兼容性，并增加数据库回归用例。

桌面打包需包含 `migrations` Python 包及其 `sql/*.sql` 资源。源代码运行从 `BACKEND_DIR/migrations/sql` 或包内 `migrations/sql` 读取资源；资源缺失时拒绝初始化，不回退到执行 `schema.sql`。

## 隔离验证

迁移测试只读取显式设置的 `TEST_DATABASE_URL`，不会回退到 `DATABASE_URL`。连接用户需要创建和删除测试 schema 的权限；每个用例使用随机 `migration_test_*` schema，结束后仅清理这些 schema。并发测试使用同一随机 schema 的独立数据库连接。

```powershell
$env:TEST_DATABASE_URL='postgresql+psycopg://USER:PASSWORD@127.0.0.1:5432/party_review_test'
.\.venv\Scripts\python.exe -m pytest backend/tests/test_migrations.py -q
```

覆盖空库初始化、重复启动、旧库与真实 dump 接管、数据与触发器保留、残缺结构拒绝、checksum 漂移、版本断档或超前、首次初始化及后续升级整批回滚、并发启动、跨 schema 同名外键修复。未设置测试连接时数据库用例跳过，跳过不视为通过。
