# 验收与自测

本文件把设计验收变成可在仓库内复现的步骤，并记录最近一次实测结果。历史交付报告中的数字属于各轮原始记录，
以本文件与各项修复记录为准。

## 复现命令

后端（需要真实 PostgreSQL；`TEST_DATABASE_URL` 跑数据库回归，`DATABASE_URL` 供 API 冒烟）：

```powershell
$env:TEST_DATABASE_URL='postgresql+psycopg://postgres:PASSWORD@127.0.0.1:5432/party_review_test'
$env:DATABASE_URL='postgresql+psycopg://postgres:PASSWORD@127.0.0.1:5432/party_review_test'
$env:APP_SECRET_KEY='test-key-0123456789abcdef'
$env:WORKER_ENABLED='0'
cd backend
..\.venv\Scripts\python.exe -m pytest -q
```

没有本机数据库时用 `tools/run_db_tests.py`（临时实例）或 `tools/pg_run.py` + 上面的变量，见
[运行与验证](RUN.md#没有本机-postgresql-时临时库跑数据库回归)。

前端：

```powershell
cd frontend
npm ci
npm test
npm run test:ui
npm run build
```

`npm run build` 会带 manifest 构建并执行体积预算检查；单独看报告用 `npm run bundle:report`。

## 体积预算

- `frontend/bundle-budget.json` 记录 35 条路由的体积上限与两条验收目标，`npm run build` 与 CI 都会强制执行；新增页面未登记预算会直接失败。
- 页面调整后用 `npm run bundle:budget` 刷新，并在提交说明里写清变大的原因。
- 除两条具名目标外，其余落地路由相对设计基线（`d6ee23a`）仍高 1.4–6.4 KiB：外壳拆成独立块后每条非登录路由
  多下载约 9.7 KiB，而入口包只减少约 8.8 KiB。这是已知取舍，预算按当前值锁定，防止继续增长。

## 权限口径

SYS_ADMIN 只保留用户、组织、设置、审计、任务和统计聚合；档案、提交包与材料正文（含原件、页面、解析、版本、差异）一律 404。
ORG_ADMIN 仍为业务全量，支部/学院/互查范围规则不变。

## 已知偏差

1. `job.result.items[].note` 不入库：确认时合并进重建结果，重新识别后不再保留。
2. `already_imported` 只出现在确认响应，`job.result` 不带该字段。
3. 指向其它任务条目的请求只返回 `item_id / status / error`，`entry_path` 等为 `null`（不读别的任务数据）。
4. 联合联调缺少“一次性通过”的成功样本，成功路径由后端用例覆盖。
5. 邮件、短信仅保存配置不投递；大模型需在系统设置配置后实测，历史报告中的精度数字不作为本轮验收。

## 结构核对

应用启动只执行带版本与校验和的迁移。结构核对以 `backend/tests/test_migrations.py` 为准：空库初始化、
重复启动不重放 DDL、旧库接管、校验和不符、并发启动都有用例；`backend/schema.sql` 是历史基线文件，不再参与启动。
