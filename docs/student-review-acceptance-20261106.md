# 2026-11-06 学生整改与支部、学院工作台验收

## 已修复

- 学生仅上传文件仍是草稿，不会自动成为支部待办。空待办和常用办理区明确说明需完成自查并“提交审核”。
- 上次报告过期时，自动问题从学生当前清单移到只读回看区，下一步优先引导重新自查。不把上传新文件视为问题已解决；已确认的退回问题和人工问题继续保留办理义务。
- 退回前已保存的说明不能代替本次整改回复。接口返回 requires_response，提交服务按本次退回时间重新校验；旧说明仍可回看，保存新回复后继续办理，操作日志记录回复内容。
- 重新提交的通知发送给实际接收层级；互查遵循当前指定人或互查支部。原权限和自动复核校验保持。
- 支部、学院首页优先列表、数字及跳转统一为本层级七日内截止及逾期待办，排除其他环节草稿。普通入口减少箭头、下划线，重复教学栏改为已有权限的常用办理入口；统计按需切换。
- 待办选择其他状态时自动放宽任务范围；切回本层级待办清除冲突状态。材料工作区为支部、学院补充统一的审核条件摘要及填写结论入口。

## 问题卡片文案与视觉补充

R-T22 缺项说明直接展示日期名称，区分“系统尚未取得日期”和“原件实际未填写”。不改写既有报告、原文或人工问题；规则代码和原始判断仍可展开查看。提交包级建议不再生成空书名号。

## 跨身份中文状态与视觉提示补充

报告摘要仅保留一个浅色AI建议标签，其余人工研判状态使用文字；材料解析状态、通知状态、历史版本、审核记录中的身份与状态均使用统一中文映射。LOW_CONFIDENCE表示自动结果还需核实，可能来自仅规则运行，并不直接等同于OCR识别失败；其他原因分别说明人工判断、业务阶段确认与材料时间冲突。

未授权发送原图时，视觉模型未执行属于配置说明，以浅灰提示展示；真实识别失败保留警告与重试。未调整任何上传授权或模型配置，未发送新的材料到外部模型。

实际网页分别验证学生、支部、学院、组织部的材料解析、版本及报告页面，并验证系统管理员用户与任务页面，包含窄屏。开发前端服务已刷新，避免旧模块缓存继续显示英文原因。共用中文词典增加约1 KiB，依实测刷新路由预算，登录125 KiB与统计150 KiB硬上限保持。
