# 后台恢复与空 OCR 复核验证

本轮在 `dev` 的 `abf2ac9` 基础上整合验证，不直接修改或合并主线。日期校正严格校验及管理员统计筛选已由 PR #34 交付；本轮补齐后台任务中断恢复及 OCR 空结果复核。

## 已实现

- 后台任务在启动和运行期间持续检查中断任务；用执行事务锁和执行代次隔离旧任务结果，遵守重试上限，批量父任务不会重复拆分。详见 [恢复约定与边界](worker-recovery.md)。
- OCR 没有识别出文字时，标为待人工复核，不当作引擎故障，也不默认为识别成功且内容合格。真实引擎故障仍按失败处理。
- 空结果重试保留已有文本、人工校正及时间节点；正式检查与规则试跑均产生独立的待复核提醒，关闭可选图片质量规则不能绕过提醒。
- 审核人员可以逐页确认已核对原图，操作经过权限和当前版本校验并记录审计；只读、历史版本不能确认。混合或多页材料仅保存文字不会默认确认空页。

## 未由这些测试证明的事项

测试中的材料和账号是隔离环境数据，不能代替真实校园 SSO、生产服务器、外部模型、干净 Windows 安装、原生 Office、真实手写与印章精度验收。前端交互测试使用隔离 API 模拟数据，不是完整浏览器端到端验收。

后台恢复不承诺外部模型请求或文件写入恰好一次；持有有效数据库事务的卡死任务需要运维终止。升级必须先停止旧 worker，不能混用旧执行进程。测试另有一条现存 Starlette TestClient/httpx 弃用警告，不影响本次通过结果。
