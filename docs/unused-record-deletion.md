# 误建账号与空档案删除验收

用户管理的“删除”仅适用于未登录、没有档案、分配或使用记录的账号。已有记录请用“编辑 → 停用”，保留办理历史。当前账号和最后一个启用的系统管理员不可删除。

发展档案的“删除空档案”只适用于未开始办理的草稿：所有阶段均需无材料（包括已删除材料）、报告、任务、审核、通知或日期记录。学生账号保留，如需清理再到用户管理删除。

两处均有身份确认弹窗，取消不发请求；失败原因留在弹窗内，可重试。删除成功刷新列表，最后一页删空时返回前一页。后端重新检查权限和关联，使用事务、行锁及数据库约束保护，并追加操作日志，不修改旧日志。

## 网页验收

1. 组织部账号在“发展档案”创建一个专用测试档案，记录学号。
2. 用户管理搜索该学号，尝试删除，应提示先处理空档案，记录仍保留。
3. 返回发展档案，点击“删除空档案”，取消后记录仍在；再次确认删除后列表移除。
4. 用户管理仍可找到该学生账号；确认删除未使用账号后移除。
5. 有材料、任务、日期或审核历史的记录应被拦截。不要为了测试而删除真实记录。
6. 支部、学院仅能管理原权限范围；互查、学生和系统管理员不能借此删除业务档案。

## 本轮验证

自动测试覆盖取消、失败重试、删除后刷新、权限范围、账号保留、重复删除、历史保护、定向互查分配保护及批量任务引用。真实浏览器仅创建并删除本轮测试记录；检查了640px窄窗口。

新增接口：`DELETE /users/{uid}`、`DELETE /archives/{aid}`（统一API前缀仍为 `/api`）。不新增数据库迁移，不调整历史不可变规则。
