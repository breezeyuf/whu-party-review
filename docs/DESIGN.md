# 设计核对基线（从包内论文还原）

本文件不是遗失的原始 design.md。原始 ZIP 的 1127 个目录项、全部 Markdown、文本与 TeX 文件中均未找到原设计文档或改名后的独立需求文档。本基线仅摘录 `workspace/paper/main.tex` 第 2、3 章中的工程要求，作为本轮调试依据；未新增党务政策或替代业务人员认定。

| 要求 | 原文位置 | 本轮核对与修复 |
| --- | --- | --- |
| 学生本人、支部、学院、组织部按当前激活角色隔离 | 2.2 用户角色与权限需求；3.6 安全设计 | 互查范围同时匹配批次、目标支部、审核支部和指定审核员；拒绝非法角色头；任务列表遵循数据范围 |
| 自查、初审、互查、复审、备案按状态流转 | 2.1.2 提交包状态机 | 拒绝未知审核动作、非当前层级接管和问题处理；备案后禁止修改材料类型、解析结果和整改回复 |
| 审核绑定实际使用的报告与材料版本 | 2.4 可追溯性；3.3.2 关键设计点 | 检测新增、替换、删除材料及后续人工校正；审核与备案拒绝过期/未完成报告；校验传入报告和问题归属 |
| 低置信度、冲突、人工研判、关键阶段必须接管 | 3.4.4 人工接管机制 | 保留全部关键阶段接管条件；接管必填原因；仅处理最新有效报告；完成接管后界面不再显示待接管 |
| 学生逐项回复后重新提交，回到退回层级 | 2.1.1 业务流程；2.3 功能性需求 | 回复限本人可编辑提交包；整改关联版本须属于对应材料/提交包；保留退回与重新提交路径 |
| 材料版本保留，原件需鉴权 | 2.3 档案与材料；3.6 文件安全 | 历史版本只读；旧版本解析任务不得覆盖当前分类和时间节点；删除材料时停用其时间抽取 |
| 后台任务异步执行，可观察、可重试 | 3.5 后台任务设计 | 保留后台队列；限定任务可见范围；手动重试清理旧终止时间并重置尝试次数 |
| 页面操作有反馈，材料与问题便于对照 | 2.4 可用性 | 抑制请求竞态和旧页面响应；刷新令牌后业务错误不退出登录；过期报告提示并禁用放行按钮 |
