# 用户导入与一次性密码文件

本次基于 `feature/ce-integrated-polish`（PR #19），独立分支为 `fix/user-import-validation`。PR 目标为该整合分支，避免重复提交整合版已有改动；不直接修改 main/dev。

## 导入行为

预校验和正式导入共用同一套整表检查。正式导入也重新校验，不依赖客户端之前的校验结果。

- 校验必需表头、重复表头、必填信息、重复账号/学号、性别和角色。
- 检查组织存在性、启用状态、操作者管理范围；学生档案须关联有效学院下的党支部。
- 检查已有账号、档案及跨工作表的姓名、组织和学生身份，避免错误关联或覆盖既有人员。
- 解析所选批次及表内 batch_name，拒绝不存在或彼此矛盾的批次。
- 日期须为 Excel 日期单元格或 YYYY-MM-DD；拒绝无效日期、公式及不存在/停用/派生的节点。
- 已有且身份一致的用户和档案保留，不修改密码或重复创建。同一文件的用户行与学生档案行可共用一个新账号。
- 任意行有错误时正式导入整批不写入；写入、角色、档案、节点及密码文件生成在同一保存点中完成，文件生成失败也回滚。
- 导入产生的匿名编号不再包含学号。

并发修改可能使正式导入与先前预校验时的数据库状态不同，因此正式导入始终重新检查；数据库唯一约束冲突会返回需重新预校验的错误。

## 密码文件

不再返回 `initial_passwords` 明文账号密码数组。创建新用户时返回：

```json
{
  "initial_passwords_file": {
    "id": 123,
    "file_name": "新账号初始密码.xlsx",
    "password": "仅本次返回的文件打开口令",
    "expires_at": "带时区的过期时间",
    "download_url": "/api/users/import-passwords/123/download"
  }
}
```

文件本身使用 Office ECMA-376 Agile 加密，须输入打开口令。数据库另外使用应用密钥加密文件内容，不保存文件打开口令；没有密码文件落盘。新账号仍使用随机初始密码并强制首次改密。

下载接口需要登录且角色为系统管理员、组织部管理员或学院审核员，并且必须是本次导入人。其他管理员也不能领取别人的文件。有效期为 24 小时，成功领取后清空加密内容并记录领取时间；数据库行锁保证同时领取只有一次成功。过期记录在 worker 定时清理中删除。导入响应及文件响应禁止缓存，下载操作写入审计。

前端显示复制文件打开口令、下载按钮和已下载状态；请求失败时保留口令并允许重试。清除结果或离开页面不会再次返回口令，已下载或过期的文件返回 410。服务端记录成功领取后，即使客户端随后网络中断也不能再次领取；必要时由管理人员重置账号密码。

## 部署

新增 `import_password_files` 表和过期索引，使用现有应用启动时的幂等 schema.sql 建表机制，不删除或重建既有表。

新增依赖 `msoffcrypto-tool==6.0.0`；Windows 锁定依赖及 PyInstaller 隐藏导入同时补齐。更新依赖并重启后生效；已有 EXE 需要重新打包。

加密 API 依据 [msoffcrypto 官方文档](https://msoffcrypto-tool.readthedocs.io/en/latest/#encryption-ooxml-only-experimental)。该库将加密功能标注为 experimental，本次完成了真实文件加密、正确口令解密、错误口令拒绝和完整性验证；原生 Excel/WPS 打开及新 Windows 包仍需在交付环境验收。
